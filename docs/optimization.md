# 最適化の方法と評価

このページでは、Just Intonation Suite が MIDI をどう解析し、どの基準で音律を最適化するかを説明します。

## 何をしているか

MIDI の調号変更を転調区間として扱い、各区間で鳴った非ドラム音のピッチクラス（C=0〜B=11）を集計します。調号情報がない場合は `music21` による小節単位の調推定にフォールバックします。最適化は、全区間に共通する12音の音律を1つ求めます。

```mermaid
flowchart LR
    M[MIDI] --> K[調号変更から区間を作成]
    K --> U[区間ごとに使用音を集計]
    U --> A[焼きなまし法で初期解を探索]
    A --> S[SLSQPで制約付き微調整]
    S --> O[12音の音律]
    O --> W[WAV再生・出力 / SCL保存]
```

## 目的関数

音律は、C を基準とした12音の `log2` オフセット `A` で表します。隣り合う音の幅を `d` として、`A[0] = 0`、`A[1:] = cumsum(d)` と構成します。したがって、最適化変数は11個の音程幅で、幅は正、合計は1オクターブ未満という制約を持ちます。

各調の主音から半音階上に進んだとき、実際の音程と目標純正比との差を計算します。目標比は `1/1, 16/15, 9/8, 6/5, 5/4, 4/3, 45/32, 3/2, 8/5, 5/3, 9/5, 15/8, 2/1` です。差は `log2` 空間で測り、二乗して平均します。本来であれば二乗平均は平方根を取るべきですが、少しでも軽量化するために処理上では取っていません。MIDI 区間で実際に使われた音とオクターブは重み1、その他の半音は重み0.0001です。複数の調があれば調ごとのスコアを平均します。

処理手順は、焼きなまし法で候補を探索し、その候補を初期値として SciPy の SLSQP で局所的に改善する流れです。CLI (`music.py`) は既定で焼きなましを2,000回行います。GUI は10回の焼きなまし試行から最良候補を選びます。

## RMS誤差低減率の定義

比較では、同じ MIDI に対して次の2つの目的関数スコアを計算します。

- **平均律ベースライン**: `A[i] = i / 12` としたときのスコア。
- **最適化後**: 焼きなまし法と SLSQP を適用した後のスコア。

スコアは誤差の二乗平均なので、比率を比較するときは平方根を取ってRMS誤差に戻します。セント換算は `RMS cent = 1200 × √score` です。

```text
RMS誤差低減率 (%) = (√平均律スコア - √最適化後スコア) / √平均律スコア * 100
```

値が大きいほど、この目的関数上では目標純正比との誤差が小さくなっています。

### 基音ペア `0 i` の実行結果

`tuner.py` に `0 1`、`0 2`、…、`0 11` を入力した場合の結果です。ここで `0` は C、`1`〜`11` は C♯〜B のピッチクラスです。これは2つの基音を同時に最適化対象にする比較で、MIDI ファイル内で1回転調する実験とは異なります。

平均律ベースラインは全ケースで同じです。各行の最適化後スコアは `tuner.py` の `optimize_A` を実行して得ました。設定は焼きなまし1,500反復を10回、その後 SLSQP で微調整です。SLSQP は全11ケースで成功しました。なお `tuner.py` は焼きなましの各試行で乱数 seed を0に戻す実装のため、10試行は同じ乱数系列から始まります。

## 現時点でできること

- 選択した基音群、または MIDI の使用音に応じた12音の音律を計算する。
- MIDI の調号変更を区間として解析し、区間で実際に鳴った音を重視して曲全体向けの音律を求める。
- 最適化した音律で WAV を合成し、チューニングを Scala `.scl` 形式で保存する。
- MIDI 入力に対してリアルタイム・シンセを使う。
